## Voice "connected but didn't hear me" fix + voice budget settle (session 4, 2026-10-30; merged in PR #3, owner-verified on laptop + iPhone)
**Owner report (production, laptop):** real-time voice "said connected but nothing happened when I spoke". Hosted `ai_usage`: 2 voice sessions minted ($0.25 each held forever → $0.50 of $2/day for two ~10 s attempts), 1 tiny turn.
**Root cause (confirmed in a reproduction, browser not known):** `voice-session.tsx` created the microphone `AudioContext` after awaits (session fetch, `getUserMedia`), outside the tap, and never resumed it. Safari (and Chrome without sticky activation) start such a context `suspended` → the worklet never runs → 0 audio sent, while the badge says "Listening". Old code under a Safari-like emulation: **0 chunks in 5 s, mic context `suspended`, "Listening" shown**. Chromium's real `--autoplay-policy=document-user-activation-required` alone does NOT reproduce (the click gives sticky activation; old code passes), which is why earlier runs missed it. A silent/wrong input device (frames sent, all silence) gives the same symptom and was invisible too; hosted data can't tell which one the owner hit (not inspected: hosted is off-limits here).
**Fix (`src/components/voice-session.tsx`):** mic context created + resumed synchronously in the "Start talking" tap (`primeMicAudio`, like `primedOutput`; also on Reconnect/Retry), resume after `getUserMedia` with a timeout (`tryResume`, Safari leaves `resume()` pending outside a gesture); `onstatechange` → status "Microphone paused" + "Tap to resume the microphone" button (iOS `interrupted`/`suspended`), "Listening" only when the mic context is running; worklet node kept in a rendered graph via a 0-gain sink (Safari pulls only nodes reaching the destination); Firefox: on `NotSupportedError` from `createMediaStreamSource` retry with a context at the track's rate (default rate otherwise); "Navi isn't hearing your microphone…" hint + "Retry microphone" when nothing above −57 dBFS (or no frames) arrived for 4 s since connect/unmute/resume; live level bar (aria-hidden) + text "Mic: picking up sound / silent / muted / paused". Only levels/timestamps kept, nothing logged. `/pcm-worklet.js` added to `PUBLIC_PATHS` in `src/proxy.ts` (static, non-personal; unauthenticated GET → 200 JS); CSP `script-src 'self'` already covers worklets; `public/sw.js` never intercepts it (not static/icons, not a navigation).
**Budget (`src/server/ai/budget.ts`, new `src/app/api/voice/end/route.ts`, session route):** reservation still taken up front ($0.25). Client reports end on hang-up/unmount (after the last turn is saved), and when a new token replaces a session. `endVoiceSession` records the server-measured mint→end seconds once in the reservation row's `audio_seconds` (0 = open) and settles via existing `ai_voice_settle` with `p_reserve = min($0.25, minutes × $0.023/min)` → session = max(reported, elapsed estimate). Never-ended sessions settle to elapsed-at-expiry (10 min = $0.23) once past expiry + 60 s, on the user's next mint/probe/turn report (`settleExpiredVoiceSessions`). Failed mints (ok=false, $0) are never re-charged. No migration.
**Evidence:** new e2e `strict browser audio rules` ×2 (desktop + iPhone; whole voice-live.spec now runs with `--autoplay-policy=document-user-activation-required`, Safari-like `AudioContext` emulation in the strict tests) — both **failed on the old build** (mic `suspended`, 0 chunks; no level/hint UI), pass on the new one; 4 new vitest cases in voice-server.test (short session → ≈elapsed, not $0.25; never-ended → reserved until expiry then $0.23; reported > estimate wins; other user's id ignored). ## Key decisions
- Next.js 16.4 (Turbopack, `proxy.ts` not middleware), `cacheComponents: false` (all per-user dynamic data).
- One domain layer used by server actions, API routes and AI tools (`src/server/ai/tools.ts`) so chat/voice/UI stay in sync.
- AI never creates inferred commitments directly: `propose_items` → inbox. `create_task` only for explicit commands; `complete_task` only when the server-held user message (or voice transcript) contains the quoted statement; otherwise one-tap approval. `update_item` patches only allowlisted columns per table.
- Planner never invents availability; never moves fixed items; never marks work done. Day plans written by the locked `replace_day_plan` function.
- Models only in `src/server/ai/config.ts` + env: fast=`claude-haiku-5-5`, planner=`claude-sonnet-5-5` (server-side refusal fallbacks "default"), voice=`gemini-3.8-live`. Forced tool_choice is a 400 on Sonnet 5.5 → auto. The backup model is used only if no tool step has run.
- Budget: aggregate across providers in `ai_usage`, day boundary `NAVI_BUDGET_TIMEZONE` (UTC default), override only by `NAVI_ADMIN_EMAILS` (≤$20/day). App guard isn't a hard cap; set provider spend limits.
- Gemini free tier is "used to improve products" → disclosed in Settings/voice UI.
- Client components import server actions from `@/app/(app)/client-actions` (network failures return `{ ok:false }` instead of crashing the page); server components pass originals to `ActionButton`.
- Scheduler: one idempotent `/api/cron/tick`; Trigger.dev task every 10 min calls it (Vercel Hobby cron is daily only).
- Tests run only against local Supabase (guard + wrapper); browser tests run in UTC.
- AI answers about state come from read tools (`get_plan`, `get_inbox`, `search_items`, `get_overview`), never chat history; one pure day-agenda builder (`src/server/planner/agenda.ts`) backs Planner, Today and `get_plan`. Read-only tool names live in `src/lib/tool-names.ts` (not shown as "actions taken").
- Block outcomes: category comes from status + reason prefix (`src/lib/outcomes.ts`); "took longer than estimated" = `skipped` + that reason, excluded from the rating like rest/interruptions/missing info but reported as a planning problem. Past unmarked blocks stay "unmarked" (counted, flagged, prompted on Today and in `/review`), never auto-"missed". Reviews/statistics come from code (`get_review`), never the model.
- Tasks have no do-date (no migration): "on Sunday" = soft `due_at` Sunday 23:59, reported as a due date, never as "scheduled". Accepted inbox questions become episodic memories.
- Planner: min block 30 min, work ≤ 60 min never split (`MIN_CHUNK_MINUTES`, `WHOLE_UP_TO_MINUTES` in scheduler.ts).
- No invented times: deterministic guard for captures (`time-guard.ts`); no all-day events (an event blocks its whole span in the planner), so an untimed "event" becomes a task due that day. Weekday numbering is 0 = Sunday everywhere; an off-by-one batch is corrected only when weekly events' own dates prove it.
- An interrupted voice reply is saved as heard (transcript up to the audio that had started playing), marked "…(interrupted)".

## Learnings
- Supabase auth hooks reload only on full `supabase stop --no-backup` + start.
- Newer hosted Supabase projects don't grant API roles table privileges by default (local does) → grants must be explicit in migrations.
- Hosted PostgREST answers HEAD for a missing table with 204 and no error → existence checks must use GET (`select().limit(0)`).
- Management API `POST /database/migrations` records the apply time as the version; fix to the file version.
- A Vercel project with no framework preset builds Next.js successfully but serves 404 for everything.
- Environment-variable edits can reach a running session (the container restarts); that restart also kills dockerd. A session's first credential check may predate the owner's edit — re-check before declaring a blocker.
- Container resets kill dockerd. If `dockerd` says "process with PID … is still running" but nothing runs: `sudo rm -f /var/run/docker.pid /var/run/docker.sock` then start it again. `npm run db:start` may need a second run ("db not ready").
- Session env vars that exist but are **empty** still block `.env.local` (dotenv and Next.js never override existing variables) → use `scripts/local-only.sh`.
- `pkill -f "next start"` can kill the calling shell; use `fuser -k 3000/tcp`.
- In dev mode, wait for `networkidle` before `context.setOffline(true)`.
- `scrollIntoView` returns a Promise in new Chromium; a concise-arrow effect returning it crashes React cleanup.
- supabase-js bulk insert with differing keys sends NULLs → insert rows separately in tests.
- This Chromium ships an unprefixed `SpeechRecognition`; test stubs must replace both names.
- DevTools `ServiceWorker.deliverPushMessage` occasionally drops a push; pwa.spec redelivers up to 3 times.
- `serviceWorker.controller` is null on first load → the page clears `*-pages` caches itself on sign-out/login.
- A server action that can't reach the server throws; in React 19 that replaced the page with the error screen → handled (see Key decisions).
- Supabase admin `createUser` bypasses the before-user-created hook, so it can't be used to probe the invite hook.
- Gemini Live: sends `interrupted` even after `generationComplete` while its audio is still playing on the client (turnComplete is paced roughly to playback), so server-side barge-in covers buffered audio. It generates a 20 s reply in ~3 s. Without explicit guidance it used Monday = 0 and `Z` times; it may give `origin` only at the item level.
- Real voice harness: Chromium `--use-fake-device-for-media-stream --use-file-for-fake-audio-capture=<wav>%noloop`, WAVs from ffmpeg `flite` + `anullsrc` silences (48 kHz mono s16); an init script wrapping `AudioBufferSourceNode.start/stop` shows what played and when it was cut.
- Supabase CLI `config.toml`: `[auth.email] enable_signup=false` disables the whole email provider (GOTRUE_EXTERNAL_EMAIL_ENABLED=false); turn off public sign-up with `[auth] enable_signup=false`. Auth config changes apply on `supabase stop` + `db:start` (data kept). Redirect allow-list entries are exact unless they end in `**`, so `/auth/callback?next=…` needs `/auth/callback**`.
- Playwright `getByRole("alert")` also matches Next's empty route announcer → scope to `main`.
- Tests that plan "today" fail late at night (no free time left before 23:59): give those accounts a zone where it's midday (`middayTimezone()`), or accept the honest "didn't fit" result.
- Read-only tool calls aren't stored in `messages.tool_events`; to see which read tool a real model used, look at what only that tool returns.
- Concurrency fixes (each with a test that failed first): proposal accept claim, guarded task completion, recurring successor, push claim + retry, locked day plan, voice tool-call dedupe, chat partial-failure honesty, voice mic release on connection loss, voice turn kept on save failure.
